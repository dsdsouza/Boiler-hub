# Focus with Pip

This implements the mentor's accountability demo **inside Boilerplate**. My Boiler keeps its existing iron-and-brass design, pressure gauge, live calendar, tasks, Pip chat, and shared controls. Focus with Pip now lives on **Connect** (`/settings/sources#study-accountability`) and uses the signed-in owner’s tasks from My Boiler. No extra app, backend service, schema migration, or hosting project is needed.

## Run and configure

Use the existing `pnpm dev` workflow and open `/settings/sources` for Focus with Pip and `/boiler` to manage its tasks. The existing server environment fields are used:

```dotenv
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-3.8-flash
```

Put the actual key in the ignored `.env.local` (or the app host's runtime secrets), then restart the local app. Never use a `NEXT_PUBLIC_` API key. Follow [Pip chat setup](./pip-chat.md) for the existing authentication and hosting configuration. Live Gemini replies need the configured key and sign-in. Both ordinary chat and course questions use Gemini Interactions with `store: false`. Missing keys and provider failures remain visible errors, with no pretend AI fallback.

## Demo: knowing what is due versus actually starting

1. Open My Boiler → **Chat with Pip**. Ask what is due next, what to prioritize, or when to study. Pip uses fresh open assignments and live calendar availability. Ask for a study block or accountability reminders: Pip prepares a concrete proposal for an open assignment, with a small goal and a 10–45 minute duration. Nothing starts until you accept its card. Missing or incomplete calendars require your explicit confirmation that the proposed time works. The existing **Plan with Pip** control also drafts a question in this visible chat.
2. In **Connect → Focus with Pip → Course material for Pip**, paste a syllabus/assignment excerpt or upload `.txt`/`.md`. Ask about deadlines, required deliverables, subject explanations, assignment answers, or help writing and debugging work. Pip cites checked quotes for claims based on the excerpts and can use general knowledge and reasoning for solutions and original drafts. Course material is optional for assignment help. Both replies and proposed study-card goals pass the shared scope review before display; assignment answers and worked solutions are allowed. Documents stay in the shared conversation memory across navigation and closing the chat, clear on reload or sign-out, and are sent to Google with the chat request. Three documents, 6,000 characters each and 12,000 combined are supported. A PDF can be copied and pasted as text.
3. Install the Pip extension: download it from the panel, unzip, visit Chrome's Extensions page, turn on Developer mode, choose **Load unpacked**, select the folder, and reload Boilerplate. Use extension **v0.3.3** and look for **Pip extension paired** in the focus panel. Choose **Enable laptop reminders** and check the test notification; allow Chrome notifications in the laptop’s settings. An existing installation needs its unpacked files replaced, its extension reloaded, and Boilerplate reloaded. Accepting Pip’s plan then hands its task, goal and times to the extension. The unpacked source also lives in `focus-extension/`.

4. Open YouTube or Reddit in another tab. Choose **10-second demo**, then return to that tab. In ten seconds Pip interrupts it with a real focus page. This is an explicitly opted-in, one-minute demonstration; it uses the same blocking path as regular sessions.
5. Pip sends a heads-up, a start reminder, a mid-block check-in, and a completion check-in (with one follow-up five minutes later). Clicking a notification opens Pip. These reminders and website blocking work with the Boilerplate tab closed; Chrome must keep running. Return to Pip, ask for help taking the first step, and work on the assignment. When the whole assignment is finished, confirm that fact and choose **Mark done & release**. This uses the existing task completion API and vent animation. Completing only a small substep does not require marking the assignment done: use **End focus** instead.

**Use my next free window** finds the first opening in the events already loaded from My Boiler, at least one minute ahead. Overlapping events are merged by advancing the proposed start past each conflict. It does not create a calendar event, and missing calendars can hide conflicts. The student explicitly opts in when scheduling; the installed extension starts blocking at that time without another click.

## Import coursework from the Pip toolbar

Extension v0.3.3 includes a toolbar popup headed **Import your coursework?**, alongside the current study-block status and **Open Pip**. This is the same single Pip install used for every onboarding goal. Open the school calendar in a regular tab, select Brightspace, Canvas, Moodle, Blackboard, or **Another calendar**, and follow the displayed feed instructions. Leave the subscription link or feed dialog visible, then choose **Find calendar links on this page**. Opening the popup does not scan the page; scanning starts only with that explicit Find click.

Choose **Use in onboarding** beside a result to open `/onboarding#feed=…` on the paired, trusted Boilerplate origin. Review the URL, name and coursework setting in the calendar step, then explicitly connect it. Students must connect at least one healthy coursework ICS source, keep all connected coursework feeds healthy, and explicitly review the imported deadlines before setup can finish. A readable empty feed has its own explicit confirmation. The server refreshes and verifies the reviewed import again at completion. Professionals are not required to add courses. See [guided onboarding](./onboarding.md) for the two-hour review receipt and saved-progress behavior.

For an independent import, choose **Review import in Boilerplate** to open `/calendar-helper`. The popup also links to Connect to connect Google Calendar or Apple Calendar. Calendar feeds bring in calendar events and deadlines, not grades or course files. See [calendar import helpers](./browser-helper.md) for provider steps and handoff boundaries. The separate Calendar Finder remains available outside onboarding.

The toolbar extends the existing iron-and-brass interface: it reuses `focus.css`, the packaged Bebas Neue and Inter fonts, and the existing Pip icon. Its compact layout and status messages are local to the popup; the incumbent design reference remains [docs/design](./design/README.md).

## Blocker boundaries

The Manifest V3 extension pauses YouTube, Instagram, TikTok, Reddit, and X. It redirects new navigations and already-open distracting tabs. School sources and Boilerplate remain accessible. It does not inspect/send browsing history to Gemini, block OS apps, control a phone, or enforce on another device. Persistent host access is scoped to the five blocked domains; the app bridge accepts `boilerplate.select`, `boilerhub.work`, `boilerplate.zhomander.workers.dev`, and documented local development ports. Calendar import uses `activeTab` and `scripting` for temporary chosen-page access, and the scanner runs only after the explicit Find click; the extension does not request persistent access to school sites.

Focus is local to the browser. Chrome stores the chosen task title, small goal, and session times so its alarms work when the app page closes. The extension releases rules at the deadline and runs a 30-second watchdog. Browser/OS scheduling or sleep can delay alarms; after waking, the next event clears expired rules. Reopening Connect restores a session only if its task is in the current person's loaded assignment list. Uploads are not stored by the extension.

The assistant and extension both offer **emergency release**. A cancelled session cannot be reactivated by a stale page. At expiry, completion, or emergency release, paused tabs return to their original addresses automatically. A tab navigated elsewhere is left alone, and closed tabs are not reopened. Return addresses stay in the paused tab’s URL fragment and are not sent to Boilerplate or stored separately. Disabling or removing the extension also immediately releases its rules, but cannot run the automatic tab return; reopen those sites manually. The timer works without the extension while the page remains open, and the app explicitly reports that blocking is not confirmed. Laptop notifications require extension v0.2.0 or later, explicit opt-in, and notification permission for Chrome. The app tab may be closed, but Chrome must remain running. Turning reminders off clears outstanding Pip notifications; ending a session stops its later reminders.

Time expiring releases blocking and asks what got done; it does not mark work complete. Completion is the student's explicit self-report, saved using the existing authenticated task API. No completion is credited when that API fails. Calendar and source integrations that already work are preserved. Gradebook and device-wide enforcement remain future work, without claims of live functionality.

## Verification

`pnpm typecheck`, `pnpm lint`, and `pnpm test` cover the integration. Added tests exercise proactive boundaries, overlap scheduling, request limits, source quote verification, the Gemini request protocol through a synthetic transport, actual-domain matching and cancellation. A synthetic provider test is not evidence of a live Gemini-generated answer.

Onboarding checks a fresh browser nonce and a supported manifest version, with v0.3.2 as its minimum. This provides installation feedback, not tamper-proof attestation. A native Brave check on October 24, 2026 confirmed the updated Pip v0.3.3 installation and its live onboarding detection, then scanned an existing Brightspace subscription, imported real coursework, reviewed sampled deadlines, and completed setup. Finish later resumed at the unfinished calendar step. This check does not establish compatibility with every school or browser.

Run `pnpm pip:package` after editing extension files. It reproducibly writes `public/downloads/boilerplate-focus-extension.zip` from the explicit file list in `scripts/package-focus-extension.mjs`, including the toolbar popup, focus/reminder files, Pip icon, and existing local fonts; test files are excluded. Packaging also copies the canonical `browser-helper/scan.js` and `browser-helper/protocol.js` into `focus-extension/imports/`, and the ZIP reads those two sources directly from `browser-helper/` to avoid scanner drift. `focus-extension/imports.test.ts` checks archive/source equality, trusted review destinations, school navigation boundaries, and the exact permission set. Existing Calendar Finder remains a separate, unchanged extension with its own `pnpm helper:package` command.
